# 项目架构

## 结论

前端与后端在代码和通信协议上独立：

- `public/` 是无构建依赖的静态前端，只通过 HTTP API 获取任务和媒体。
- `server.mjs` 是后端，负责队列、远梦 API、重试、下载、SQLite 和文件生命周期。
- 默认由后端同时托管 `public/`，因此一个容器即可开箱运行。
- 如果需要物理分离，可把 `public/` 部署到任意静态服务器，并在 `public/config.js` 中填写后端地址；后端通过 `ALLOWED_ORIGINS` 放行前端域名。

这意味着“逻辑独立、默认一体部署、可拆分部署”。

## 数据流

```text
浏览器粘贴分享内容
       │ POST /api/tasks
       ▼
任务创建与 JSON 持久化
       │
       ▼
串行任务队列（一次一个，间隔 3 秒）
       │
       ├─ 解析短链/分享长链 → 标准 douyin.com/note|video 地址
       ├─ 调用远梦 API（密钥只存在后端）
       ├─ 超时/上游失败 → 任务进入重试列表，主队列跑完后逐个拉回
       └─ 每任务最多 3 路并发下载媒体
                          │
                          ├─ SQLite 分配作者作品序号
                          ├─ data/tasks/<task-id>/ 保存媒体和 task.json
                          ├─ 以作品 ID 去重并原子归档到家庭云 NAS
                          └─ 浏览器首次同步后通过 SSE 接收任务状态，并从本地文件接口播放/下载
```

## 并发与重试

- 任务严格串行：同一时刻只处理一个任务，任务结束后固定间隔 3 秒再开始下一个；队列空闲时新提交的任务立即开始，不等待间隔。
- 双解析通道：远梦 API 优先（全局单通道 + 熔断器追踪健康度）；远梦出现基础设施故障（连接失败/超时/5xx/熔断）时，自动切换残像 API 兜底解析，熔断冷却到点后由下一个任务自然完成远梦探测，成功即切回远梦。远梦明确判定链接无效时不兜底。
- 远梦 API 相邻请求启动间隔不少于 3 秒。
- 每个任务内部最多同时下载 3 个媒体文件。
- 所有外部请求均有超时：分享跳转 20 秒、解析 API 35 秒、媒体下载 120 秒。
- 失败任务进入重试列表，不使用退避定时器；主队列（首次任务）全部完成后，重试列表里的任务按同样的 3 秒节拍逐个拉回执行，仍失败则继续回到重试列表，循环直到成功或达到尝试上限。
- 已成功取得解析结果的任务若在媒体下载或 NAS 归档阶段失败，重试时复用解析结果，不再次消耗远梦 API 请求。
- 默认最多尝试 8 次（熔断等待不消耗次数）；无法识别、不支持或无效链接属于永久错误，不浪费重试。
- 连续基础设施故障默认达到 3 次后开启全局熔断 180 秒。熔断期间任务在重试列表队首等待且不消耗重试次数；冷却结束后按节拍只放行一条半开探测，成功才恢复全部请求，失败则重新冷却。
- `/share/slides/<ID>`、`/note/<ID>` 与 `/video/<ID>` 都会被规范化为稳定的作品地址，移除易过期的分享查询参数。
- 自动重试和手动重试统一经过同一个串行调度器，任何入口都同时只会有一个任务在执行。
- 服务重启时，未完成任务从磁盘恢复并重新排队；完成任务继续可用直到独立过期。

这套模型适合单台服务器上的多用户并发使用，但不是分布式队列。不要直接启动多个后端副本共享同一个 `data/` 目录；如需横向扩容，应把任务队列迁移到 Redis/消息队列，把媒体迁移到对象存储。

## 持久化

```text
data/
├─ naming.sqlite          作者序号与任务命名映射，长期保留
├─ naming.sqlite-wal      SQLite WAL 文件（运行时可能存在）
└─ tasks/
   └─ <task-id>/
      ├─ task.json        任务状态、解析结果、到期时间
      ├─ 作者名.jpg
      ├─ 作者名.mp4
      └─ 作者名.mp3
```

- 每个任务从创建时间起独立保留 `TASK_TTL_HOURS`，默认 24 小时。
- 任务到期会删除整个任务目录，但 SQLite 作者序号继续保留，确保后续作品仍使用 `.2`、`.3`。
- SQLite 使用 WAL 和同步事务，作者序号在并发任务下不会重复。

## NAS 永久归档

- `archive.mjs` 是独立归档模块；Web 任务的 24 小时生命周期与 NAS 永久档案互不影响。
- `archive_records` 以抖音作品 ID 为唯一键，同一作品重复或并发解析不会生成重复目录。
- `archive_author_sequences` 独立维护每位作者的归档序号，目录固定为 `UP主/UP主（1）`、`UP主/UP主（2）`。
- 文件先写入同一父目录下的隐藏 `.part` 临时目录，媒体、说明和校验清单全部成功后才原子改名；失败会清理半成品并进入既有重试机制。
- 每份档案包含媒体、`作品信息.txt`、完整的 `原始数据.json` 和带文件大小及 SHA-256 的 `归档清单.json`。
- 容器只挂载 `NAS_ARCHIVE_PATH` 指定的归档目录，不需要获得整个 NAS 的访问权限。

## 安全边界

- `.env` 不进入镜像和版本库，API Key 不下发给浏览器。
- 远梦 API Key 通过 HTTPS `Authorization: Bearer` 请求头发送。
- 只接受抖音及 iesdouyin 域名，降低任意 URL 请求风险。
- Docker 默认只绑定 `127.0.0.1:4173`，由 Nginx 对外提供 HTTPS。
- 当前应用没有账号登录。若发布到公网，必须在 Nginx、Cloudflare Access 或其他入口增加访问控制，不能直接裸露端口。

## 目录结构

```text
douyin-parser-web/
├─ public/                 独立静态前端
│  ├─ index.html           任务工作台
│  ├─ task.html            任务详情页
│  ├─ app.js               首页交互和 SSE 实时状态
│  ├─ detail.js            详情数据和媒体展示
│  ├─ config.js            前后端分离时的 API 地址
│  └─ styles.css           视觉系统、响应式与动效
├─ data/                   运行数据，不打包、不提交
├─ deploy/                 Nginx 与 systemd 示例
├─ docs/                   架构、API、部署文档
├─ server.mjs              后端、队列与静态文件服务
├─ archive.mjs             NAS 去重、命名、原子归档与完整性清单
├─ Dockerfile
├─ compose.yaml
├─ .env.example
└─ package.json
```
